# hh-search

Личный автопоиск вакансий на hh.ru. Работает сам, раз в несколько часов:
обходит листинги, отсеивает заведомо чужое, оценивает оставшееся по вашему
профилю и складывает **только новые находки** отчётом на диск. Настроите
Telegram — будет присылать их же в канал.

**Проблема, которую он решает.** Поиск работы — это не поиск, а дежурство:
интересное появляется в случайный момент и тонет за сутки. Смотреть выдачу
руками каждый день утомительно, а раз в неделю — поздно. Плюс глаз замыливается:
пятидесятую вакансию читаешь не так, как первую. Сервис берёт на себя дежурство
и одинаково внимателен к каждой.

Своими руками остаётся то, чего машина не сделает: описать, что вам интересно,
и решить по короткому списку.

## Быстрый старт

```bash
mkdir -p data/config data/state data/reports data/logs
cp config.example/*.yaml data/config/
$EDITOR data/config/app.yaml       # свой contact_email — обязательно
$EDITOR data/config/profile.yaml   # свой город в home_areas и summary

# uid контейнера обязан совпадать с владельцем ./data
printf 'HH_UID=%s\nHH_GID=%s\n' "$(id -u)" "$(id -g)" >> .env

docker compose build
docker compose run --rm hh-search init-db
docker compose run --rm hh-search run    # первый прогон, посмотреть глазами
docker compose up -d                     # дальше сам
```

Отчёты появятся в `data/reports/`, логи — в `data/logs/hh.log`.

**Две правки в образцах пропускать нельзя.** `contact_email` — заглушка
отвергается на старте: адрес уезжает в `User-Agent` и служит hh.ru
единственным способом связаться с нами вместо того, чтобы забанить. И
`home_areas` в `profile.yaml` — там города автора конфига, а с чужим домашним
регионом каждая вакансия ВАШЕГО города тихо потеряет очки.

Если uid не совпал, сервис не отдаёт трейсбек, а называет причину и действие
одной строкой; развёрнутое объяснение ловушки — в [`.env.example`](.env.example).

Telegram настраивается отдельно и не обязателен —
[как](docs/reports.md#telegram).

## Как это устроено

Семь шагов, и порядок в них — главное решение проекта:

```
листинги → дедупликация → отсев по заголовку → страница вакансии
        → оценка → запись в базу → отчёт
```

**Дешёвое стоит до дорогого.** Отсев по заголовку — единственный барьер перед
сетью: он убирает заведомо чужое, не заплатив ни одного запроса за страницу.

**Сохранение стоит до отправки, а отправка выбирает из базы, а не из памяти.**
Поэтому авария между шагами ничего не теряет: перезапуск продолжает с того же
места, а описание каждой вакансии скачивается ровно один раз за всё время.

**Порог делит отчёт, а не отсекает.** Ниже порога вакансии видны, просто
свёрнуты в одну строку. Этот раздел и есть обратная связь по качеству профиля:
регулярно попадается стоящее — значит настройки подобраны неверно.

### Вежливость к hh.ru — не украшение, а условие работы

Публичный API для соискателей закрыт, поэтому источник — курируемые листинги и
страницы вакансий. Соблюдаются: честный `User-Agent` с контактом, `robots.txt`,
одно соединение за раз с паузой, `Retry-After`. Авторизация, куки и эмуляция
браузера не применяются. Устойчивый отказ доступа **останавливает** сервис, а
не заставляет искать обход.

`robots.txt` разбирается **собственным матчером** по RFC 9309, а не
`urllib.robotparser`: стандартный не понимает подстановок, поэтому правила вида
`Disallow: *?*` он не видит вовсе и разрешает запрещённое. Недоступен или не
разобрался — запрещено всё.

> **Текущее ограничение.** hh.ru убрал из `robots.txt` разрешение
> постраничного обхода, и с августа 2026 доступна только первая страница
> каждого листинга. Объём добирается **шириной** — несколькими разными
> листингами вместо нескольких страниц одного. Подробнее в
> [настройке](docs/configuration.md#queriesyaml--где-искать).

### Оценка: ключевые слова решают, модель советует

Балл считается **по ключевым словам** из вашего профиля — детерминированно,
без сети и одинаково от прогона к прогону. Он и только он определяет, что
попадёт в отчёт.

Локальная модель (см. ниже) на это решение **не влияет никак**. Она отвечает
за порядок внутри одинаковых баллов и за подписи рядом с вакансией.

## Локальная модель: зачем и что будет без неё

Две модели через [Ollama](https://ollama.com), обе на вашей машине — наружу не
уходит ничего, ключей и подписок не нужно. **По умолчанию выключены.**

**Зачем.** Ключевые слова хорошо отвечают на вопрос «есть ли в вакансии то, что
я перечислил», и плохо — на «а про что она вообще». Отсюда три вещи, которых
регулярным выражением не получить:

| Что даёт | Как видно в отчёте |
|---|---|
| **Порядок внутри одинаковых баллов** — их больше половины | колонка `semantic`, 0…1 |
| **Что в вакансии названо** — стек и грейд, включая то, чего вы не искали | `stack`, `seniority` |
| **Переезд из текста** — «работа предполагает переезд в Самару» | `relocation` |
| **Мнение и одна строка почему** | `llm_score`, `llm_reason` |

**Эффект, самый наглядный.** Вакансия «Системный архитектор / Tech Lead»: по
разметке страницы регион — посёлок Волжский, балл высокий, стоит в верху
отчёта. В тексте описания: *«Работа предполагает переезд в г. Самара.
УДАЛЁННЫЙ ФОРМАТ РАБОТЫ НЕ РАССМАТРИВАЕТСЯ!»* Штраф за регион этого не видел
никогда — он считается по полю разметки. Теперь видно, с городом и пометкой
«требуется».

Второй эффект тише, но постояннее: «находка дня» в Telegram раньше выбиралась
из нескольких вакансий с **одинаковым** баллом порядком, который не задан
ничем. Теперь — по смысловой близости к профилю.

**Чего модель не делает.** Не решает, какие вакансии вы увидите. Не двигает
порог. Не меняет балл. Её мнение — сигнал, а не измерение, и потому
показывается, а не действует.

**Что будет, если не подключать.** Ровно тот же отчёт, что и сейчас: те же
вакансии, тот же порядок, тот же статус прогона. Колонки просто пусты. То же
самое — если Ollama выключена, недоступна, отвечает мусором или молчит: в лог
уйдёт **одна** строка за прогон, и прогон пойдёт дальше. Проверено исполнением
на пяти способах сломаться.

Цена: близость — около полуминуты на весь архив, остальное — примерно
полторы секунды на вакансию. Обе роли включаются отдельными флагами.

Установка, выбор моделей, доступ из WSL и все замеры —
[Локальная модель](docs/local-llm.md).

## Разработка

```bash
uv sync --frozen --extra dev
./gate                       # ворота: линтер, формат, типы, тесты без сети
uv run pytest -m network     # контрактные тесты против живого hh.ru
uv run pytest -m llm         # контрактные тесты против живой Ollama
```

Состав ворот живёт в `gate` и больше нигде — CI зовёт этот же скрипт.

Контрактные тесты — ранняя система оповещения: если hh.ru изменит разметку,
уберёт JSON-LD или перепишет `robots.txt`, они об этом скажут. В воротах не
участвуют, чтобы сборка не зависела от живой выдачи.

**Часть тестов сторожит не код, а документ.** `test_spec_matches_code.py`,
`test_config_example.py` и `test_claude_md.py` сверяют с фактом инвентарь
модулей, DDL, образцы конфигов, набор команд CLI, колонки отчёта и пути из
`CLAUDE.md`. Заведены не для красоты: ревью показало, что с кодом разошлись
РОВНО те разделы документов, которых не сторожил ни один тест, а все
сторожимые оказались безупречными. Покраснел такой тест — правьте документ
вместе с кодом, а не выключайте сторожа.
