# hh-search

**Автопоиск вакансий на hh.ru, который дежурит вместо вас.** Сам обходит
листинги, оценивает каждую вакансию по вашему профилю и раз в несколько часов
отдаёт короткий список — только новое, только по делу. На диск в Markdown, CSV и
HTML; в Telegram — если подключите.

## Зачем это нужно

Искать работу — значит дежурить у выдачи: хорошие вакансии появляются в
случайный момент и через сутки тонут в ленте. Ежедневно смотреть руками —
утомительно, раз в неделю — поздно. hh-search снимает эту рутину:

- **Ничего не пропускает.** Обходит все ваши листинги по расписанию и
  замечает каждую новую вакансию, когда бы она ни вышла.
- **Показывает только новое.** Что вы уже видели — в отчёт не попадёт; в
  Telegram каждая вакансия приходит один раз.
- **Считает балл по вашему профилю.** Ключевые слова, стоп-слова, зарплата,
  регион, формат работы — всё из одного файла `profile.yaml`, который вы пишете
  под себя.
- **Одинаково внимателен к первой и к пятидесятой.** У сервиса не замыливается
  глаз: балл считается детерминированно и не меняется от прогона к прогону.
- **Не портит отношения с hh.ru.** Соблюдает `robots.txt`, ходит с честным
  `User-Agent`, делает паузы между запросами и останавливается при отказе.
- **Понимает текст, если дать ему локальную модель.** Опционально через Ollama:
  стек, грейд, требование переезда и короткое мнение по каждой вакансии — всё
  на вашей машине.

Вам остаётся то, чего машина не сделает: описать, что вам интересно, и
выбрать из короткого списка.

первой строкой — «находка дня».

## Быстрый старт

```bash
mkdir -p data/config data/state data/reports data/logs
cp config.example/*.yaml data/config/
$EDITOR data/config/app.yaml       # contact_email
$EDITOR data/config/profile.yaml   # home_areas и summary

# uid контейнера должен совпадать с владельцем ./data
printf 'HH_UID=%s\nHH_GID=%s\n' "$(id -u)" "$(id -g)" >> .env

docker compose build
docker compose run --rm hh-search init-db
docker compose run --rm hh-search run    # первый прогон — посмотреть глазами
docker compose up -d                     # дальше сам, по расписанию
```

Отчёты появятся в `data/reports/`, лог — в `data/logs/hh.log`.

Две правки в образцах конфигов обязательны:

1. **`contact_email` в `app.yaml`.** Адрес уходит в `User-Agent`: это
   единственный способ для hh.ru связаться с вами вместо того, чтобы забанить.
   С заглушкой сервис не стартует.
2. **`home_areas` в `profile.yaml`.** В образце — города автора. Оставите как
   есть — вакансии вашего города будут тихо терять очки как «чужие».

Если uid не совпал, сервис не падает с трейсбеком, а называет причину и что
делать одной строкой; подробности ловушки — в [`.env.example`](.env.example).
Telegram подключается отдельно и не обязателен — [как](docs/reports.md#telegram).

## Как это работает

Один прогон — семь шагов, и их порядок важнее любого из них:

```
листинги → дедупликация → отсев по заголовку → страница вакансии
        → оценка → запись в базу → отчёт
```

- **Сначала дешёвые проверки, потом сеть.** Заведомо чужое отсеивается по
  заголовку ещё в листинге — страница такой вакансии не скачивается вовсе.
- **Сбой ничего не теряет.** Каждая вакансия сохраняется в базу раньше, чем
  попадает в отчёт, а отчёт собирается из базы. Перезапуск продолжает с того же
  места, и описание каждой вакансии скачивается ровно один раз за всё время.
- **Порог не прячет, а сворачивает.** Вакансии ниже порога остаются в отчёте
  одной строкой. Это обратная связь по профилю: если там регулярно попадается
  стоящее — настройки надо поправить.
- **Балл считают ключевые слова, и только они.** Локальная модель, если
  подключена, не двигает балл и порог: она упорядочивает вакансии с одинаковым
  баллом и добавляет подписи.

## Честный обход hh.ru

Публичный API для соискателей закрыт, поэтому источник — курируемые листинги и
страницы вакансий. Правила, которых сервис держится:

- честный `User-Agent` с вашим контактом;
- `robots.txt` соблюдается буквально — собственным матчером по RFC 9309,
  потому что стандартный `urllib.robotparser` не понимает подстановок вроде
  `Disallow: *?*` и разрешает запрещённое; недоступен или не разобрался —
  запрещено всё;
- одно соединение за раз, пауза между запросами, уважение к `Retry-After`;
- никакой авторизации, куки и эмуляции браузера;
- устойчивый отказ доступа **останавливает** сервис, а не заставляет искать
  обход.

> **Ограничение с августа 2026.** hh.ru убрал из `robots.txt` разрешение
> постраничного обхода, и доступна только первая страница каждого листинга.
> Объём добирается шириной — несколькими листингами вместо нескольких страниц
> одного. Подробнее в [настройке](docs/configuration.md#queriesyaml--где-искать).

## Локальная модель (по желанию)

Две модели через [Ollama](https://ollama.com), обе на вашей машине: наружу не
уходит ничего, ключей и подписок не нужно. По умолчанию выключены.

Ключевые слова хорошо отвечают на вопрос «есть ли в вакансии то, что я
перечислил», и плохо — на «а про что она вообще». Модель закрывает этот пробел:

| Что даёт | Где в отчёте |
|---|---|
| Порядок внутри одинаковых баллов — а их больше половины | `semantic`, 0…1 |
| Стек и грейд из текста, включая то, чего вы не искали | `stack`, `seniority` |
| Требование переезда, спрятанное в описании | `relocation` |
| Мнение и одна строка «почему» | `llm_score`, `llm_reason` |

Самый наглядный случай — вакансия «Системный архитектор / Tech Lead»: по
разметке регион — посёлок Волжский, балл высокий, стоит наверху. А в тексте:
*«Работа предполагает переезд в г. Самара. Удалённый формат не
рассматривается!»* Штраф за регион считается по полю разметки и этого не видел
никогда. Теперь переезд виден — с городом и пометкой «требуется».

Модель **не решает**, какие вакансии вы увидите, не двигает порог и не меняет
балл: её мнение — сигнал, а не измерение. Если Ollama не подключена, выключена,
недоступна или отвечает мусором, отчёт будет ровно тем же — те же вакансии, тот
же порядок, просто пустые колонки и одна строка в логе. Проверено на пяти
способах сломаться.

Цена: около полуминуты на весь архив для близости и примерно полторы секунды
на вакансию для остального. Установка, выбор моделей, доступ из WSL и замеры —
[Локальная модель](docs/local-llm.md).

## Разработка

```bash
uv sync --frozen --extra dev
./gate                       # линтер, формат, типы, тесты без сети
uv run pytest -m network     # контрактные тесты против живого hh.ru
uv run pytest -m llm         # контрактные тесты против живой Ollama
```

Состав ворот живёт в `gate` и больше нигде — CI зовёт этот же скрипт.

Контрактные тесты — ранняя система оповещения: если hh.ru изменит разметку,
уберёт JSON-LD или перепишет `robots.txt`, они об этом скажут. В ворота не
входят, чтобы сборка не зависела от живой выдачи.

Часть тестов сторожит не код, а документы: `test_spec_matches_code.py`,
`test_config_example.py` и `test_claude_md.py` сверяют с фактом инвентарь
модулей, DDL, образцы конфигов, команды CLI и колонки отчёта. Ревью показало,
что с кодом разошлись ровно те разделы, которых не сторожил ни один тест.
Покраснел такой тест — правьте документ вместе с кодом, а не выключайте
сторожа.
