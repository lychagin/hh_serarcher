# Локальная модель

Две модели через [Ollama](https://ollama.com), обе на вашей машине: ничего не
уходит наружу, ключей и подписок не нужно.

| Модель | Роль | Цена прогона |
|---|---|---|
| `bge-m3` (эмбеддинги) | близость вакансии к профилю | ~30 с на весь архив |
| `qwen2.5:7b` (текстовая) | стек, грейд, переезд, мнение | ~1.6 с на вакансию |

**Выключено по умолчанию.** У работающей установки секции `llm` в `app.yaml`
нет вовсе, и обновление не должно само начинать ходить в сеть за моделью,
которой на той машине может не быть.

```yaml
llm:
  base_url: auto          # вычислит адрес хоста сам; можно указать явно
  chat_model: qwen2.5:7b
  embed_model: bge-m3
  timeout_sec: 60
  semantic: true          # порядок внутри одинаковых баллов
  facts: true             # стек, грейд, переезд, мнение
limits:
  llm_per_run: 200
```

## Установка

```bash
ollama pull bge-m3
ollama pull qwen2.5:7b
```

Про выбор текстовой модели: `qwen2.5:7b` занимает 4.4 ГБ и целиком помещается
в 8 ГБ видеопамяти. Четырнадцатимиллиардная версия (~9 ГБ) туда уже не влезет
и частью уедет на процессор — это втрое медленнее при не столь заметном
выигрыше.

## Если Ollama на Windows, а сервис в WSL или в контейнере

Ollama слушает только `127.0.0.1`, и из WSL до неё не достучаться. Открывается
на стороне Windows:

```powershell
setx OLLAMA_HOST "0.0.0.0"
# выйти из Ollama в трее и запустить снова — переменная читается при старте.
# дальше от администратора:
New-NetFirewallRule -DisplayName "Ollama WSL" -Direction Inbound `
  -Protocol TCP -LocalPort 11434 -RemoteAddress 172.17.32.0/20 -Action Allow
```

Перезапуск Ollama обязателен: `setx` пишет переменную в реестр, а уже
запущенный процесс её не перечитывает.

Проверить из WSL:

```sh
curl -s http://$(ip route | awk '/default/{print $3}'):11434/api/tags
```

Адрес шлюза WSL меняется при перезагрузке Windows — поэтому `base_url: auto`
вычисляет его при каждом старте, а не хранится в конфиге. Контейнер ходит
иначе, через `host.docker.internal`; `compose.yaml` уже задаёт и хост, и
переменную `HH_LLM_BASE_URL`, которая старше конфига.

Проверить живую модель отдельно от остальных тестов:

```bash
uv run pytest -m llm
```

Они пропустятся с внятной причиной, если Ollama недоступна: недостижимая
модель — состояние машины, а не дефект.

## Что каждая роль даёт

### Близость к профилю (`semantic`)

Косинус между вектором описания и вектором профиля. **Разрывает связки**
одинаковых баллов и никогда не обгоняет балл: вакансия с меньшей оценкой не
может подняться выше вакансии с большей.

Форма выбрана замером, а не осторожностью. По всему архиву у 246 из 539
отсеянных вакансий косинус выше, чем у худшей прошедшей порог, — весом в балл
он потянул бы наверх почти половину отсева. Зато внутри связок разводит
содержательно, а связок выше порога больше половины.

Чинит конкретную поломку: «находка дня» в Telegram выбиралась из нескольких
вакансий с одинаковым баллом порядком, который не задан ничем.

### Факты из текста (`stack`, `seniority`)

Что в описании **названо**, включая технологии, которых вы не искали. Не
дубликат оценки: балл считается по сигналам из `profile.yaml`.

Роли разведены замером: 7–8-миллиардная модель **берёт** из текста заметно
лучше, чем **судит** о нём. С одной и той же вакансии она выдавала константу
в роли оценщика и точно выписывала весь стек в роли извлекателя.

### Переезд (`relocation`)

Закрывает измеренную дыру: штраф за регион считается по полю разметки, а
«работа предполагает переезд в Самару, удалённый формат не рассматривается»
живёт в **тексте** описания. Вакансия с чужим `area` проходила мимо штрафа
целиком.

Разделение труда здесь обратно ожидаемому, и это тоже замер. **Находят
слова**, без модели: спрошенная напрямую, она нашла 5 упоминаний из 11,
пропустив ровно деловые формулировки вроде «релокационный пакет, оплатим
дорогу и первый месяц аренды». Технический смысл («переезд приложений в
Kubernetes») отсеивается тоже без модели — класс «речь не о людях» она не
выбрала ни разу.

**Модель называет город и отличает требование от льготы**: «требуется:
Елабуга» — не то же, что «по желанию: Кипр». Спрашивается она только там, где
переезд уже найден словами, — около 6% вакансий.

### Мнение (`llm_score`, `llm_reason`)

Оценка вакансии и одна строка почему. **Ни на балл, ни на порядок отчёта не
влияет** — модель высказывается, решаете вы. Спрашивается только у вакансий
выше порога: ниже его мнение никто не прочитает.

Смотреть стоит на **расхождения** с баллом. Они ложатся не случайно, а там,
где оценка по ключевым словам высока за общие слова роли, не замечая чужого
стека:

```
балл 94 → мнение 35   Technical Team Lead (C# / Python)   «стек не соответствует»
балл 87 → мнение 25   C#/.NET Backend Developer
балл 83 → мнение 25   Senior backend developer (PHP, Symfony)
балл 69 → мнение 20   Ведущий инженер (Backend/Embedded)   «релокация в Елабугу»
```

**Обращаться с этим числом надо как с сигналом, а не как с измерением.** Оно
детерминировано при заданном промпте (три вызова подряд дают одно и то же), но
ходит от мелких правок его формулировки: лишнее поле в схеме сдвигает оценку
на десять пунктов, другое описание профиля — на пятьдесят. Именно поэтому оно
показывается, а не действует.

Практическое следствие: **правка `profile.summary` — повод перемерить**.

## Если модели нет

Недоступная, медленная или врущая модель даёт **ровно тот же отчёт**, что и
прогон без неё вовсе: те же вакансии, тот же порядок, тот же статус прогона.
Проверено исполнением на пяти способах сломаться — отвергнутое соединение,
таймаут, не скачанная модель, мусор вместо ответа, неполный ответ.

Отказ не понижает статус прогона до `partial` по той же причине, по которой
его не понижает недоступный Telegram: модель живёт на машине, которая
выключается на ночь, и `partial` стоял бы каждый прогон подряд, перестав
значить что-либо. В лог уходит **одна** строка ERROR за прогон, не двести.

Колонки отчёта в этом случае просто пусты, а порядок остаётся тем, каким был
бы без модели: сортировка устойчива, и отсутствующая близость не двигает
ничего.

## Смена модели

Правка `embed_model` или `chat_model` обесценивает уже посчитанное **сама**:
имя модели лежит в базе рядом с её результатом, и вакансии возвращаются в
очередь без ручной чистки. Чистить базу руками не надо и не следует.

Вектор `bge-m3` и вектор любой другой модели живут в разных пространствах —
косинус между ними посчитается, выйдет правдоподобным и не будет значить
ничего. Именно от этого и защищает имя рядом с данными.

## Почему не LangChain

Нужны ровно два обращения по HTTP. `langchain-ollama` разрешается в 32 пакета,
включая клиент телеметрии, при четырёх рантайм-зависимостях у всего проекта.
Новых зависимостей от локальной модели — **ноль**.
