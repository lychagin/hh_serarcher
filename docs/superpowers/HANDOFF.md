Локальная LLM встроена: **семантическое ранжирование, извлечение фактов и

В `main` не влито.

**Ближайший шаг: две находки прогона ниже, обе про hh.ru и обе важнее LLM.**

## Действие владельца: доступ к Ollama

Ollama слушает `127.0.0.1:11434`, из WSL до неё не достучаться (проверено
`netstat` 2026-08-26). На стороне Windows:

```powershell
setx OLLAMA_HOST "0.0.0.0"
# выйти из Ollama в трее и запустить снова
# от администратора:
New-NetFirewallRule -DisplayName "Ollama WSL" -Direction Inbound `
  -Protocol TCP -LocalPort 11434 -RemoteAddress 172.17.32.0/20 -Action Allow
```

Проверка: `curl -s http://$(ip route | awk '/default/{print $3}'):11434/api/tags`
из WSL, затем `uv run pytest -m llm` — контрактные тесты к живой модели.

Пока порт закрыт, брандмауэр пакеты ОТБРАСЫВАЕТ, а не отвергает: клиент ждёт
таймаута. Поэтому таймаут соединения разведён с таймаутом чтения (5 с против
`llm.timeout_sec`), и худшее, чем это грозит прогону, — двадцать лишних секунд.

## Что сделано

Спека — `docs/superpowers/specs/2026-08-26-local-llm-design.md`, и она же
источник всех чисел ниже. Замеры делались через `curl.exe` с Windows-стороны.

| Возможность | Кто делает | Цена прогона |
|---|---|---|
| порядок внутри одинаковых баллов | `bge-m3`, косинус к профилю | ~1 мин |
| стек, требуемый опыт, грейд | `llama3`, JSON Schema | ~5 мин |
| переезд: есть или нет | слова, без сети | 0 |
| переезд: город и вид | `llama3`, только у ~6% | ~15 с |

Включается двумя флагами в `app.yaml` (`llm.semantic`, `llm.facts`), **по
умолчанию выключено**: у работающей установки секции `llm` нет вовсе, и
обновление не должно само начинать ходить в сеть.

## Три замера, каждый переопределил решение

1. **llama3 как оценщик не годится.** Три релевантные вакансии (ключевая
   оценка 87.3) — все три `score: 60`. Обещание §4.2 старой спеки про
   `LlmScorer` замером опровергнуто, и он не строится.
2. **Семантика не двигает порог.** Замер на двенадцати лучших и десяти худших
   давал ПОЛНОЕ разделение; тот же замер на всех 573 показал наложение в 246
   вакансий. Поэтому косинус — строгий разрыватель связок, а не слагаемое
   оценки. Связок выше порога 55%, и «находка дня» в Telegram до этого
   выбиралась из четырёх вакансий с оценкой 87.3 произвольно.
3. **Фильтр-отсев не построен.** Из четырёх возражений модели выше порога одно
   убило бы «AI Tech Lead» — вакансию, прямо отвечающую профилю. Вместо отсева
   закрыт переезд, ради которого фильтр и был ценен (§0.6, §0.7 спеки).

## Открытые задачи

### hh.ru УБРАЛ из robots.txt разрешение пагинации — найдено прогоном 2026-08-26

Живой `robots.txt` больше не содержит двух строк, на которых стояла вся
discovery проекта:

```
Allow: /vacancies/*?page=        ← БОЛЬШЕ НЕТ
Allow: /vacancies/*?*&page=      ← БОЛЬШЕ НЕТ
```

Вердикты собственного матчера проекта на живых правилах против фикстуры
`tests/fixtures/robots_hh.txt`:

| адрес | было | стало |
|---|---|---|
| `/vacancies/programmist` | разрешён | разрешён |
| `/vacancies/programmist?page=1` | разрешён | **ЗАПРЕЩЁН** |
| `?work_format=REMOTE&page=0` | разрешён | **ЗАПРЕЩЁН** |
| `/vacancy/123456` | разрешён | разрешён |

Клиент отказался ходить сам и был прав — обходить нельзя. Но следствия
серьёзные, и решать их владельцу:

1. **`pages: N` в `queries.yaml` больше ничего не значит** сверх первой
   страницы: доступен только голый путь. Прогон 2026-08-26 дал 100 найденных
   вместо прежних сотен.
2. **Второй поток discovery по `work_format=REMOTE` мёртв целиком** — вся его
   форма URL накрыта `Disallow: *?*`. Спека
   `2026-07-30-region-and-work-format-design.md` описывает работающим то, чего
   больше нет.
3. **CLAUDE.md утверждает неверное.** Раздел «Внешняя система: hh.ru» называет
   три формы листинга; законной осталась одна.
4. **Сторож green, а реальность разошлась.** `test_live_robots_allows_listing_and_vacancy_pages`
   гоняет ФИКСТУРУ, снятую когда-то, и потому зелен. Ровно тот урок, который в
   CLAUDE.md уже записан: «живая фикстура — условие необходимое, но не
   достаточное». Здесь она устарела молча.

Ничего из этого не правилось: смена стратегии discovery — решение владельца, а
не починка по ходу. Фикстура и спека НАМЕРЕННО оставлены как есть, чтобы
расхождение было видно, а не затёрто.

### DNS в контейнере мерцает, и один сбой стоит всего прогона

Замер 2026-08-26: `nn.hh.ru` не резолвится в **2 попытках из 15 внутри
контейнера** (из WSL — 0 из 15). Голые пути листингов редиректят именно на этот
поддомен.

Один сбой убивает прогон целиком, и это по построению: отрицательный вердикт
`robots.txt` кэшируется на весь прогон вместе с типом отказа
(`PoliteClient._robots_denied`). Кэш заводился против 403 — чтобы отказ
источника не усиливал давление на него, — но **временная сетевая ошибка
кэшируется наравне с сознательным запретом**. Три прогона подряд из четырёх
погибли так.

Возможное решение (не сделано, не заказано): не кэшировать отказ, причина
которого — сеть, а не ответ сервера. Отличать их есть чем: тип исключения уже
лежит в кэше рядом с сообщением.



### Прогон `run` с живой моделью и живым hh.ru не делался

Приёмка шла на КОПИИ базы и без похода в hh.ru и Telegram: слать в канал ради
проверки незачем. Всё, что зависит от самой модели, проверено (числа ниже);
непроверенным остаётся только стык с discovery, которого правка не касалась.

Замеры приёмки на копии рабочей базы (573 вакансии с описанием):

| Что | Число |
|---|---|
| миграция старой базы до новой схемы | применилась |
| векторы всего корпуса | **573 за 30.9 с** (пачками по 20) |
| факты | 40 за 65.4 с → 1.6 с на вакансию |
| вектор профиля | 0.1 с |
| множество выше порога с моделью и без | **совпало** |
| порядок отчёта | изменился |

Внутри связки 87.3 косинус развёл вакансии 0.639 / 0.639 / 0.612 / 0.574 — то
есть ровно так, как обещал §0.2.1. В отчёт живьём попали строки вида
`_стек: Go, Python · senior_` и `_**переезд в Анталья — по желанию** · стек: …_`.

### Больший вес семантики — решение отложено до глаза владельца

§6 спеки: складывать косинус в `total` нельзя (замер), но насколько он полезен
в спорной середине — не знает ни один из двух замеров. Косинус печатается
рядом с оценкой именно затем, чтобы владелец посмотрел сам.

### Обслуживание Telegram зависит от доступности hh.ru — прежняя задача, не тронута

При устойчивом `403` `run_once` пробрасывает `AccessForbidden` мимо вызова
`report()`, а `maintain_sinks` зовётся только изнутри него. Застрявший документ
не довозится, пока источник недоступен. Подробности — в предыдущей редакции
этого файла (`git log`).

### Спека ретенции без сторожащего теста — прежнее наблюдение, не тронуто

`2026-08-01-retention-and-resilience-design.md` не сверяется ни одним тестом
целиком. По правилу проекта это вопрос времени, а не «если».

## Чему научила эта волна

Сторож деградации проходил **вхолостую**, и нашлось это мутацией. Тест вида
«сломанная модель ничего не меняет» по построению не отличает сломанную модель
от НЕПОДКЛЮЧЁННОГО шага: пока не появился положительный сторож, весь шаг можно
было удалить из `run_once` при зелёных тестах. Тот же класс, что
`WorkFormatBlockStats`, — третий раз в этом проекте.

Из двадцати с лишним новых сторожей мёртвыми при первой проверке оказались
девять. Все девять чинились не переписыванием кода, а добавлением случая,
которого тест не исполнял.
