# Отчёты: где смотреть и что там написано

Прогон не печатает найденное в терминал — там только итоговая строка со
счётчиками. Всё, что он нашёл, лежит в томе `./data`.

| Что | Путь | Чем открывать |
|---|---|---|
| Отчёт для чтения | `data/reports/<ГГГГ-ММ-ДД>-new.md` | редактор с превью markdown |
| Тот же для телефона | `data/reports/<ГГГГ-ММ-ДД>-new.html` | браузер; его же приёмник `telegram` шлёт файлом |
| Та же выдача таблицей | `data/reports/<ГГГГ-ММ-ДД>-new.csv` | Excel/LibreOffice двойным кликом |
| Полные данные | `data/state/hh.db` | `sqlite3`: описания целиком, разбивка балла, история статусов |
| Ход прогона | `data/logs/hh.log` | глазами; там же причины пропусков и отказов |

Файл дня один: второй прогон тех же суток дописывает в него, а не заводит
новый, и повторы отсекает сам приёмник. HTML пишется только при включённом
приёмнике `telegram`.

Отчёт можно пересобрать из базы, ничего не запрашивая у hh.ru:

```bash
docker compose run --rm hh-search report --since 7d
```

## Markdown

Делится на два раздела. `## Топ` — вакансии с баллом не ниже
`report_threshold`, сгруппированные по кластеру (`### backend`, `### lead`, …),
каждая с компанией, регионом, зарплатой, форматом работы, датой публикации и
началом описания. `## Остальное` — всё, что ниже порога, по одной строке.

**Порог делит отчёт, а не отсекает**: под ним вакансии видны, просто свёрнуты.
Раздел «Остальное» и есть обратная связь по качеству профиля — если там
регулярно попадается что-то стоящее, порог или сигналы подобраны неверно.

Под вакансией «Топа» может стоять строка от локальной модели:

```
**[Ведущий инженер](https://hh.ru/vacancy/…)** — 68.7 · близость 0.671

_**переезд в Елабугу — требуется** · стек: C, Linux, Yocto · senior_

> модель: 20 — обязательная релокация не соответствует профилю кандидата
```

Переезд стоит первым: это единственная часть строки, способная закрыть
вакансию целиком. Подробнее — [Локальная модель](local-llm.md).

## CSV

UTF-8 с BOM и разделителем `;` ради Excel:

```
id;score;cluster;title;company;area;salary_from;salary_to;currency;published_at;listing;url;work_formats;semantic;stack;seniority;relocation;llm_score;llm_reason
```

Балл записан числом, поэтому сортировка по нему и фильтр по зарплате работают
прямо в таблице. Новые колонки всегда дописываются **в хвост**: колонка в
середине сдвинула бы все поля после себя для того, кто читает файл дня по
заголовку прошлой версии, — молча.

Последние шесть колонок заполняет локальная модель, и пустые ячейки в них
значат «не считалось» (модель выключена, недоступна или описание снято
уборкой), а не «плохо»:

| Колонка | Что это |
|---|---|
| `semantic` | близость описания к профилю, 0…1. В балл **не входит**, порог не двигает — упорядочивает вакансии с ОДИНАКОВЫМ баллом |
| `stack`, `seniority` | выписанное из текста вакансии: не дубликат оценки, а то, что в описании названо, включая технологии, которых вы не искали |
| `relocation` | переезд, найденный в тексте: `требуется: Самара` или `по желанию: Кипр` |
| `llm_score`, `llm_reason` | мнение модели и одна строка почему. На балл и порядок **не влияют** |

Смотреть в `llm_score` стоит не на само число, а на **расхождения** с баллом:
балл 94 при мнении 35 обычно означает, что ключевые слова поймали роль, а стек
вакансии вам чужой.

## Telegram

Приёмник `telegram` шлёт в приватный канал «Топ» сообщением и полный отчёт дня
HTML-файлом. HTML, а не markdown: телефон открывает его браузером, и ссылки
остаются кликабельными.

Что сделать один раз:

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Создать приватный канал.
3. Канал → *Управление* → *Администраторы* → **Добавить администратора** →
   найти бота → оставить право **Публикация сообщений**. Поиск ищет по УЖЕ
   назначенным, поэтому сначала нажимайте «Добавить администратора». Если бот
   не находится — напишите ему `/start`.
4. Написать в канал любое сообщение и открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`; `channel_post.chat.id` —
   искомый `chat_id`, он отрицателен.
5. Вписать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`.
6. Добавить `telegram` в `sinks` в `app.yaml`.

Если хоть одна переменная не задана, а `telegram` в `sinks` есть — процесс
отказывает на старте, до первого запроса. Пустой прогон в канал ничего не
шлёт: при `interval_hours: 4` иначе набегало бы шесть пустых сводок в сутки.

### Устройство сообщения

Строка с датой и счётчиками, карточка лучшего совпадения, затем остальные
вакансии выше порога — в сообщение идут первые 7 по баллу, считая карточку,
— и честный хвост про остаток, который лежит в файле. Значки 🔥 / ⚡ / ▫️
отмечают балл: 80 и выше, 70–79.9, ниже 70. У карточки значка нет: её место
занимает ★.

Счётчик шапки говорит «новых N», где N — сколько записал ЭТОТ запуск, а не
сколько вакансий появилось на hh.ru. Зарплата сокращена (`450–600k ₽`); полная
строка осталась в файле дня и в CSV.

### Проверка доставки

`report --since 7d` гоняет уже собранную базу через те же приёмники и в сеть к
hh.ru не ходит вовсе — но **доставит только в первый раз**. Приёмник
дедуплицирует по файлам дня: сегодняшнему и предыдущим суткам, число которых
задаёт `LOOKBACK_DAYS` в `sinks/base.py`. Второй запуск ничего не шлёт и
печатает `telegram: 0` с кодом 0 — это ожидаемое поведение.

Чтобы проверить доставку заново, возьмите другой `--since`. Удаления одного
лишь сегодняшнего `-new.html` для этого **недостаточно**: приёмник заглядывает
ещё на 2 предыдущих суток, и если ссылка сохранилась в одном из тех файлов, не
отправится ничего. Убирайте файлы за сегодня и за эти сутки тоже — вместе с
пустыми отметками `.sent` рядом с ними (проще всего
`rm data/reports/<ГГГГ-ММ-ДД>-new.html*`). Отметка означает «этот файл дня уже
уехал документом»: по её отсутствию приёмник узнаёт документ, который
анонсировало сообщение, а доставить не смогло, и довозит его следующим
прогоном.
